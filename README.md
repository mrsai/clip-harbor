# ClipHarbor · 链接港湾

Windows 剪贴板磁力 / 电驴链接管理，以及电脑与手机的局域网文件、文本互传。

## 下载与运行

在 [Releases](https://github.com/mrsai/clip-harbor/releases) 下载最新的 `ClipHarbor-Setup-<版本>.exe` 安装，或下载 Windows ZIP 解压运行 `ClipHarbor.exe`。适用于 Windows 10/11 x64。安装包目前未进行代码签名。

## 使用

1. 点击「开启监听」，随后复制包含 Magnet 或 ed2k 文件链接的文本。应用每 300ms 检查一次剪贴板，按 CRLF、LF、CR 和 Unicode 换行拆分，忽略空行与非链接行。开启时也收集当前剪贴板。应用自身的复制不会再次收集。捕获后自动选中对应区域；窗口失焦或最小化仍在主进程检查，无需点击收集按钮。
2. 少于 n 条进入「常用」；达到 n 条创建随机名称的独立区域；超过 m 条创建 `ceil(数量 / m)` 个子区域，每组最多 m 条，保留余数。默认 n=5、m=50，设置要求 `1 ≤ n ≤ m ≤ 10000`，修改影响后续收集，常用区立即按新的 m 检查分组。常用区累积超过 m 也会分组。链接原顺序和重复条目均保留。
3. 点击「导入文件」，支持 UTF-8、带 BOM 的 UTF-16，以及 GB18030 文本（包括 TXT、MD、Markdown、LOG、CSV、TSV 等），可提取 Markdown 链接和列表中的链接，文件中的有效链接始终创建单独区域，超过 m 条自动分组。单个文本文件上限 20 MB。不解析 PDF、Word 或种子文件。
4. 左侧每个区域旁都有复制按钮，父区域复制全部子区域。区域名称直接在输入框编辑，回车或离开输入框保存。每条链接可以显示二维码。区域可删除，常用区域可清空；「清空全部数据」需二次确认，会停止互传服务，删除收藏、区域、互传记录和应用接收的文件，保留 n/m 设置及你原先分享的源文件。退出自动保留链接与规则，下次启动默认不监听。
5. 在「局域网互传」点击「启动互传服务」，手机连接同一 Wi-Fi 并扫码。如果存在多张网卡，可切换二维码地址，选择实际 Wi-Fi / 以太网地址。Windows 防火墙首次提示时允许专用网络访问；路由器需允许设备互访。
6. 电脑添加文件或发送文字后，手机刷新共享内容即可下载或复制；手机上传后，电脑点击「另存为」保存文件。手机端支持多文件上传和上传进度，每次最多 20 个文件，单个上限 2 GB。HTTP 页面不支持现代剪贴板 API 时提供选中文字复制。

## 数据与网络

- 界面底部显示实际文件路径，可点击「打开位置」。数据是本地 JSON 文件，并非只在内存中；互传记录仍只在当前会话内。
- 链接和规则保存在 `%APPDATA%/ClipHarbor/groups.json`，使用临时文件替换保存。历史文件读取失败会保留原文件并退出，避免覆盖。macOS 开发时在 `~/Library/Application Support/ClipHarbor`（以 Electron 实际 userData 路径为准）。
- 互传列表仅当前运行有效，收到的文件保存在 userData 下的 `received` 文件夹，退出不会删除。请在退出前将需要的文件「另存为」。重启后不会自动重新分享收到的文件或之前选中的文件。
- 互传只公开主动添加的内容，不公开链接收藏或任意磁盘目录。每次启动随机生成 192-bit 访问码，停止服务即断开连接，重新启动后旧二维码失效。
- 按要求使用明文 HTTP，持有二维码地址的设备可查看并发送共享内容。仅在可信局域网使用，不要做公网端口转发。
- 窗口最小化后可继续监听；关闭窗口退出应用并停止服务。

## 开发与构建

```sh
npm ci
npm test
npm start
npm run build:win -- --publish never
```

Windows 产物在 `dist/`。GitHub Actions 在 main 更新后测试并编译，产物保留在 Actions artifacts；推送 `v*` 标签会创建 Release 并上传安装包与 ZIP。

技术栈：Electron、Node.js 内置 HTTP、Busboy 流式上传、QRCode。没有云服务或遥测。

## 验证范围

`npm test` 覆盖链接解析、n/m 边界与拆分余数、文件导入分组、配置校验、HTTP 访问码和跨站校验、双向文字/文件收发、下载字节一致性、访问码轮换。Windows 原生运行仍需在 Windows 设备上验收。
